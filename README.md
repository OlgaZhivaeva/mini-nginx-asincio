# Mini-Nginx on Asyncio

Асинхронный reverse HTTP-прокси сервер на Python, написанный с использованием библиотеки `asyncio`. 
Проект реализует основные функции прокси-сервера: парсинг протокола, балансировку нагрузки, 
управление таймаутами и ограничение соединений.

Проект спроектирован с учётом сетевых аномалий:
- Закрытие сокетов гарантируется через блоки `finally`.
- Ошибки `OSError` при разрыве соединений клиентами обрабатываются без падения сервера.
- Защита от медленных клиентов и зависших апстримов через систему таймаутов.
- Защита от перегрузок (C10k) и исчерпания ресурсов с помощью `asyncio.Semaphore` (раздельные лимиты на число клиентов и подключений к каждому апстриму).
- Предотвращение взаимных блокировок (Deadlocks). При обработке `Expect: 100-continue` прокси не блокируется в ожидании тела клиента до получения ответа от бэкенда, 
 что исключает ложные срабатывания `408 Request Timeout`.

## Особенности реализации

- **Поддержка HTTP/1.1**: корректная обработка заголовков, поддержка `Chunked Transfer Encoding` и `Trailers`.
- **Строгая валидация (RFC 7230)**: защита от атак типа HTTP Framing/Smuggling, проверка корректности заголовков `Content-Length` и `Transfer-Encoding`.
- **Поддержка `Expect: 100-continue` (RFC 7231)**: двухфазная отправка больших запросов (`POST`/`PUT`). Прокси проксирует промежуточный статус` 100 Continue` и корректно обрабатывает ранний отказ апстрима (например, `413 Payload Too Large` или `401 Unauthorized`) без чтения тела клиента.
- **Балансировка нагрузки**: распределение запросов между бэкендами по алгоритму Round-Robin.
- **Управление таймаутами**: 4-фазная система контроля времени (на подключение, чтение, запись и общий таймаут запроса).
- **Лимиты соединений**: ограничение максимального количества одновременных клиентов и подключений к каждому бэкенду через `asyncio.Semaphore`.
- **Стриминг данных**: перекачка байтов с использованием механизма Backpressure (`drain`).

## Технологии

- **Python 3.10+**
- **Asyncio**: асинхронный ввод-вывод.
- **Pytest**: автоматизированное тестирование (unit и интеграционные тесты).
- **Uvicorn**: используется как тестовый бэкенд (Echo App).

## Запуск и тестирование проекта

### Настройка окружения

Склонируйте репозиторий. Создайте и активируйте виртуальное окружение.

```bash
git clone https://github.com/OlgaZhivaeva/mini-nginx-asincio.git
cd mini-nginx-asincio
python -m venv .venv
```
Для Linux:
```bash
source .venv/bin/activate
```
Для Windows:
```bash
.venv\Scripts\activate
```
Установите зависимости.
```
pip install -r requirements.txt
```

### Конфигурация

Отредактируйте `config.yaml` под ваши нужды:

```yaml
listen: "127.0.0.1:8080"
upstreams:
  - host: "127.0.0.1"
    port: 9001
  - host: "127.0.0.1"
    port: 9002
timeouts:
  connect_ms: 1000
  read_ms: 15000
  write_ms: 15000
  total_ms: 30000
limits:
  max_client_conns: 1000
  max_conns_per_upstream: 100
logging:
  level: "info"
```

### Тесты

Запуск набора тестов (unit и интеграционных тестов парсера , балансировки, 
таймаутов и лимитов)

```bash
pytest
```

### Запуск бэкендов

В разных терминалах запустите два экземпляра эхо-сервера

```bash
python -m uvicorn proxy.tests.echo_app:app --host 127.0.0.1 --port 9001

python -m uvicorn proxy.tests.echo_app:app --host 127.0.0.1 --port 9002
```

### Запуск прокси сервера

```bash
python -m proxy.main
```

### Отправка запроса от клиента

```bash
curl -v http://127.0.0.1:8080/test
```

### Нагрузочное тестирование

Проект протестирован с помощью утилиты **k6**. Тест эмулирует нагрузку до 10 
одновременных виртуальных пользователей в течение 25 секунд.
 
Установите [k6](https://grafana.com/docs/k6/latest/set-up/install-k6/)

Для Linux
```bash
sudo apt-get update
sudo apt-get install k6
```

Для Windows (через Chocolatey)
```bash
choco install k6
```

Убедитесь, что запущены оба бэкенда (`uvicorn`) и прокси-сервер (`main.py`).

Запустите скрипт нагрузки из корня проекта:

```bash
 k6 run proxy/tests/load_test.js
```
